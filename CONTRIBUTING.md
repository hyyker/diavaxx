# Contributing to diavaxx

Keep the application static, private and easy to understand. Prefer a small named function over a compressed expression. Explain assumptions and non-obvious decisions with short comments. Avoid adding infrastructure for a feature that plain browser APIs can handle.

## Source map

| File                            | Responsibility                                             |
| ------------------------------- | ---------------------------------------------------------- |
| `src/app.js`                    | State loading, persistence, navigation and event routing   |
| `src/catalog.js`                | Stable disease IDs, combination vaccines and source URLs   |
| `src/plans.js`                  | Country/age checklists and documented reference targets    |
| `src/status.js`                 | Pure status decisions, including supported illness history |
| `src/model.js`                  | Schema, validation, V1 migration and entry helpers         |
| `src/views.js`                  | Overview, disease rows, history and guide markup           |
| `src/forms.js`                  | Vaccination, illness and plan editing                      |
| `src/transfer.js`               | Compact encoding, bounded decoding and QR parts            |
| `src/transfer-ui.js`            | Transfer preview, QR rendering, image and camera scanning  |
| `src/ui.js`                     | Shared dialog, escaping and notification helpers           |
| `src/theme.js`, `src/style.css` | Appearance and responsive layout                           |
| `tests/model.test.js`           | Pure rule, schema, transfer and QR tests                   |
| `tests/e2e/tracker.spec.js`     | Browser interactions and persistence                       |

## Before proposing a change

```sh
npm ci
npm run format
npm test
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

Add focused regression coverage for behavior changes. For visual changes, inspect desktop and phone widths in light and dark modes, including forms and the QR display. Check keyboard focus, labels and overflow. Emulation cannot fully establish physical camera behavior.

Use synthetic health records in tests and screenshots. Never commit personal backups or attach them to an issue.

## Changing clinical reference data

Use primary WHO, THL, BMG or RKI sources. Read the publication date and check whether later guidance supersedes it. Update `docs/sources.md`, the source review date, explanatory UI notes and tests together. Distinguish primary courses from boosters, vaccination from antibody prophylaxis, and a reference count from an individual recommendation.

Country selection must not overwrite personal overrides or histories. Only add automatic illness credit when a cited source supports that disease-specific rule; infection is not generically equivalent to a dose. Broader age bands need explicit eligibility caveats in the chooser.

## Preserving records

- Keep the existing local-storage key so updates can find prior data.
- Validate before saving and show errors instead of pretending a write succeeded.
- Preserve extension bags when editing objects. Render all user-provided strings as text or escape them.
- Keep the frozen V1 fixture unchanged. It was generated by the original implementation.
- Never reorder or reuse disease IDs in the transfer wire table. Display order is independent.
- Add optional future data inside the documented extension bags, or introduce an explicit schema migration. Reject incompatible input without overwriting the current record.
- Test exact round trips, including IDs, empty records, Unicode, illnesses, reminders, settings and extensions.

See [the transfer specification](docs/transfer-format.md) before changing serialization.
